# Retro — 0.9.0, opening on the work (2026-09-04)

**Scope:** `feat/skip-dead-air`. The real-time head clip now starts where the
printer starts moving.

## What went well

- **Measuring the footage decided the design.** The instinct was a configurable
  offset — "skip the first N seconds" — which would have needed tuning per
  printer and per print. Scoring the actual frames showed the boundary is
  detectable: seconds 1-5 at exactly 0.000, sustained movement from 29s. A
  measurement replaced a knob.
- **The noise in that data shaped the rule.** There is a lone 0.037 blip at t=0
  with silence either side. An instantaneous threshold — the obvious
  implementation — would have fired on it and skipped nothing. Requiring motion
  across consecutive seconds is what makes the detection correct rather than
  merely plausible.
- **Only the head needed it.** The body samples one frame per ~9 seconds, so
  half a minute of idling is three frames. Recognising that avoided seeking into
  a concat demuxer input for no visible gain.

## What was hard to understand

- **The request did not parse literally, and the literal reading was wrong.**
  "The five seconds before the first frame we will use in the timelapse" — but
  the body starts at frame 0, so there is nothing before it. The actual
  complaint was that the opening showed the printer sitting still. Restating the
  problem rather than implementing the words produced a better feature: skip the
  dead air, rather than shift a window that had nowhere to shift to.
- **Failure has to degrade to the old behaviour, not to nothing.** A detection
  that misfires late would clip the start of a print — the exact thing being
  fixed. `motion_start` returns 0.0 on anything inconclusive, and the cap bounds
  a late hit, so the worst case is what shipped yesterday.

## Follow-ups landed in this milestone

- The timelapse opens on the first layer rather than on a still machine.
- Detection failure is explicitly designed to land on the previous behaviour.

## Follow-ups blocked (and why)

- **Tuning the thresholds.** `0.02` over 3 seconds, a 120-second cap, 5-second
  bookends — all fit one print's footage well. Changing them now would be
  fitting noise; the case for adjusting is several prints where they visibly
  misjudge.
